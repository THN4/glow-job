# 3. Data Schema — the `CvProfile` contract

This is the **most important document for the future frontend**. Every card on the Review Profile screen maps 1:1 to a section below. The schema lives in `data-pipeline/src/resume/schemas/cv_extraction.py` (Pydantic; fields are snake_case in Python and **camelCase on the wire**) and is used for:

1. the AI output format (structured outputs),
2. validating `PUT /api/profiles` bodies,
3. the frontend types, generated from the backend's OpenAPI document (`/openapi.json`).

## 3.1 Design rules

- **ID-card-scan style:** every extracted item carries `confidence` and `needsReview`. The UI shows a "Please confirm" badge when `needsReview === true`.
- **Never invent:** unknown values are `null` (scalars) or `[]` (lists), never `""` or a guess.
- **Dates** are strings: `"YYYY"` or `"YYYY-MM"`. Ongoing items use `isCurrent: true` and `endDate: null`.
- **Stable IDs:** every list item has an `id` (generated by the backend, not the AI) so the frontend can edit, delete and reorder items safely.
- **Source tracking:** `source` is `"cv"` for extracted items and `"user"` for items the user added or edited, which is useful for analytics and for re-running extraction later.

## 3.2 Shared types

```ts
type Confidence = "high" | "medium" | "low";
type Source = "cv" | "user";

interface FieldMeta {
  confidence: Confidence;   // how sure the extractor is
  needsReview: boolean;     // drives the "Please confirm" badge
  source: Source;
}

interface CatalogMatch {
  status: "matched" | "unmatched";
  skillId: number | null;
  canonicalName: string | null;
  matchMethod: "exact_canonical" | "exact_alias" | null;
}
```

## 3.3 `CvProfile`

```ts
interface CvProfile {
  schemaVersion: 1;

  personal: {
    fullName: string | null;
    headline: string | null;          // e.g. "Full-stack developer"
    email: string | null;
    phone: string | null;
    location: string | null;
    links: { label: string; url: string }[];   // LinkedIn, GitHub, portfolio
  } & FieldMeta;

  summary: string | null;             // the profile / objective paragraph, as written

  education: Array<{
    id: string;
    degree: string | null;            // "B.Sc."
    fieldOfStudy: string | null;      // "Computer Science"
    institution: string | null;       // "Chulalongkorn University"
    startDate: string | null;         // "2020"
    endDate: string | null;           // "2024"
    isCurrent: boolean;
    gpa: string | null;               // kept as text: "3.45 / 4.00"
    description: string | null;       // honors, thesis topic, notable coursework (only if written)
  } & FieldMeta>;

  technicalSkills: Array<{
    id: string;
    name: string;                     // display label: Unicode/whitespace cleanup only; not a catalog canonical name
    rawName: string | null;            // original skill label returned by the extractor
    catalogMatch: CatalogMatch | null; // backend lookup against core.skills + core.skill_aliases; never guessed by Gemini
    category: "language" | "framework" | "database" | "cloud" | "devops" | "data" | "other";
    // Same scale as the database's user_skills.proficiency_level / market target_level.
    proficiency: "unknown" | "beginner" | "intermediate" | "advanced" | "expert";
    proficiencyBasis: "explicit" | "inferred" | "unknown";   // "explicit" = the CV states it; "inferred" = estimated from months of use
    evidence: Array<{                 // where the CV shows the skill in use (-> user_skill_evidence)
      evidenceType: "experience" | "project" | "resume_text";
      itemId: string | null;          // id of the experience / project, when the evidence is an item
      text: string | null;            // short quote or description
    }>;
  } & FieldMeta>;

  softSkills: Array<{ id: string; name: string } & FieldMeta>;

  experience: Array<{
    id: string;
    title: string | null;             // "Freelance Web Developer"
    organization: string | null;      // "Self-employed"
    employmentType: "full-time" | "part-time" | "internship" | "freelance" | "contract" | "volunteer" | null;
    location: string | null;
    startDate: string | null;         // "2023-06"
    endDate: string | null;
    isCurrent: boolean;               // "Present"
    description: string | null;       // short summary, as written
    highlights: string[];             // bullet points
    technologies: string[];           // ["React", "Next.js", "Node.js", "Tailwind CSS"]
  } & FieldMeta>;

  projects: Array<{
    id: string;
    name: string | null;              // "MODNOI"
    description: string | null;
    role: string | null;
    url: string | null;
    startDate: string | null;
    endDate: string | null;
    technologies: string[];           // ["Next.js", "TypeScript", "PostgreSQL", "Vercel"]
  } & FieldMeta>;

  certifications: Array<{
    id: string;
    kind: "certification" | "award" | "competition" | "workshop" | "activity";
    name: string | null;              // "AWS Workshop"
    issuer: string | null;            // "AWS Cloud Practitioner Workshop"
    date: string | null;              // "2024-03"
    detail: string | null;            // "Finalist", "Top 10"
  } & FieldMeta>;

  tools: Array<{ id: string; name: string; catalogMatch: CatalogMatch | null } & FieldMeta>;   // Figma, Jira, VS Code, …

  languages: Array<{
    id: string;
    name: string;                     // "Thai", "English"
    proficiency: string | null;       // "Native", "IELTS 7.0"
  } & FieldMeta>;

  // Computed by the backend from the data above (recomputed when the user saves edits). Optional for old clients.
  derived: {
    yearsExperience: number | null;   // merged durations of the jobs, e.g. 3.25
    currentJobTitle: string | null;
    educationLevel: "high_school" | "diploma" | "associate" | "bachelor" | "master" | "doctorate" | "other" | null;
    fieldOfStudy: string | null;      // of the highest degree
    suggestedStatus: "student" | "employed" | "career_switcher" | null;   // a suggestion; the user decides in onboarding
  } | null;
}
```

## 3.4 Extraction response envelope

A finished extraction job (`GET /api/cv/extractions/{jobId}` → `result`) wraps the profile with metadata the UI may need:

```ts
interface CvExtractionResult {
  profile: CvProfile;
  meta: {
    extractionId: string;          // = jobId, for support/debug
    provider: string;              // provider family, currently "gemini" or "mock"
    model: string;                 // provider's model identifier
    promptVersion: string;         // bump when extraction instructions change
    profileSchemaVersion: number;  // API profile contract
    extractionSchemaVersion: number; // structured model-output schema
    processingVersion: string;     // deterministic preprocessing/post-processing
    durationMs: number;
    inputKind: "text" | "images";  // extracted text, or page images (scans/photos)
    cached: boolean;               // true = same file + extraction configuration seen in the last 24 h
    detectedLanguage: "en" | "th" | "mixed";
    pageCount: number | null;
    warnings: string[];            // e.g. "Image is blurry; some text may be missed"
    reviewCount: number;           // how many items have needsReview = true
  };
}
```

## 3.5 What the AI produces vs. what the backend adds

The AI does **not** produce `id`, `source`, `needsReview` or `schemaVersion`. Those are deterministic and added in post-processing, which keeps the AI schema smaller and the rules testable.

| Field | Produced by |
|---|---|
| all content fields, `confidence` | AI (structured output) |
| `isDocumentACv`, `detectedLanguage`, `warnings` | AI (top-level fields of the extraction schema, not part of `CvProfile`) |
| `id`, `source`, `schemaVersion` | Backend |
| `needsReview` | Backend rule: `confidence !== "high"` **or** a required field (e.g. `institution`, `title`) is null |
| skill name normalization, dedupe | Backend (`skill_aliases.py`), applied after the AI call |
| `technicalSkills[].proficiency` (explicit levels only, else `"unknown"`) | AI; **for text CVs the backend re-reads the level from the CV text** (`derive.explicit_level_from_text`) and drops levels the text doesn't show |
| `proficiencyBasis`, inferred levels | Backend (`derive.py`): months of use from the jobs/projects that list the skill (< 2 y beginner, 2-5 y intermediate, 5 y+ advanced, never "expert"); a matching certification lifts it to at least intermediate |
| `technicalSkills[].evidence` | Backend: the experiences/projects that list the skill, else the CV sentence that mentions it |
| `derived` (years of experience, current job title, education level, field, suggested status) | Backend (`derive.derive_profile`) |

## 3.7 Versioning

`schemaVersion` starts at `1`. Any breaking change (renaming or removing a field) bumps it, and the backend keeps a migration function for stored profiles. Adding optional fields is non-breaking. Extraction metadata separately records prompt, profile-schema, extraction-schema, and processing versions so a model result can be traced without changing the profile's version for an additive field.
